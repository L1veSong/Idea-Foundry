# 计划文档质量规范

> 2026-06-26 实战提炼。用户反复要求「写了目的吗？」「每一步为什么这样做」。

## 计划文档必备四要素

### 1. 目的（Purpose）

每个计划/阶段必须有目的章节。回答：这个阶段要验证什么核心假设？为什么值得投入？

```
❌ 目标：部署 API
✅ 目的：验证三件事——①算法能通过 HTTP 正确运行 ②远程可调 ③架构可行。三问全过，阶段一结束。有一个不行，不继续。
```

### 2. 每一步带「为什么」

不是技术原因，是决策逻辑。面向双重读者——执行者和介绍对象。

```
❌ 任务3：部署到 Mac Mini
✅ 任务3：部署到 Mac Mini
   为什么：本机是我日常用的电脑，不能当 24h 服务器。Mac Mini 专门干这件事。
   为什么 scp 二进制不装 Go：Mac Mini 保持干净，尽量不装东西。
```

### 3. 量化完成标准

不是「API 能跑」，是可验证的门槛。

```
❌ 完成标准：API 通了
✅ 完成标准：
   - [ ] 外部开发者从公网调 POST /v1/session/start，拿到 session_id + 刺激值
   - [ ] 连续调 response，直到 status: "completed"
   - [ ] 最终阈值结果正确
   - [ ] 服务连续运行 24h 不崩溃
```

### 4. 风格：专业 + 可读

专业人员能看，小白也能跟读。术语保留但要解释。不假设读者知道所有背景。

```
❌ scp binary to Mac Mini, start with launchd
✅ 把编译好的文件通过网络拷贝到 Mac Mini（scp），设置成开机自动启动（launchd）
```

## 交付物清单写法

每个交付物附带「为什么」，而非仅仅「是什么」：

| 交付物 | 为什么要这个 |
|--------|-------------|
| server.go | 原程序是命令行交互（等键盘输入）。API 需要等 HTTP 请求。改 main() 不改算法 |
| psychotest 二进制 | 拷到 Mac Mini 直接跑，不需要装 Go。单文件、零依赖 |
| API Key | 鉴权。没有 Key 谁都能调等于裸奔 |
| 公网地址 | Mac Mini 在内网，Ngrok 打通隧道让外面能访问到 |

## 三阶段模板

```
阶段一：验证核心链路（最小投入，最大风险）
阶段二：验证市场需求（有了骨架再投入）
阶段三：验证商业可持续（有用户再推广）

每阶段定义：
- 核心假设
- 验证标准（可量化）
- 做完的 vs 故意跳过的（附推到哪个阶段）
```

## 内部文档守则

- 不写「全自研」「无合作方」——内部文件不用说这个
- 不写你举例给我听的参考模型（和风天气/高德）——那是讨论素材，不是文档内容
- 计划写完给用户审查——别闷头干
