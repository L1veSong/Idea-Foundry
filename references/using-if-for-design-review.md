# 用法：用 IF 逼问已有设计

## 触发场景

用户已经有一个完整设计（非新建项目），想用 IF 的批判性思维找出漏洞。

典型触发语：
- "过一遍 IF 看看能不能逼问出更多想法"
- "用 IF 审查这个方案"
- "跑 IF 逼问一下"

## 流程

与新建项目不同，设计审查走精简路径：

```
Phase -4: 策略选择 → ⚡ 极速模式（不做能力扫描，直接进入质疑）
  ↓
逼问 1..N: 每个边界场景 → clarify() 选择题 → 用户选 → 记录决策
  ↓
汇总: 所有决策 → 更新设计文档
```

## 逼问清单模板

| 维度 | 逼问方向 |
|------|---------|
| 崩溃 | 组件挂了怎么办？ |
| 过期 | 数据/缓存过期了怎么办？ |
| 膨胀 | 数据越来越多会炸吗？ |
| 依赖 | 组件之间有顺序要求吗？ |
| 滥用 | 会不会太频繁触发？ |
| 冲突 | 和现有系统打架吗？ |
| 污染 | 错误数据会扩散吗？ |
| 自噬 | 会攻击自己吗？ |

## 实战案例

2026-06-04：SSR（智配路由）插件设计审查。8 轮逼问产出 8 项设计决策，包括：
- 技能扫描失败 → 弹窗不静默
- 描述过期 → 每次启动重建索引
- LLM 模型能力 → 先做再测
- 执行顺序 → 阶段标签
- 连续消息优化 → 任务切换检测
- A 层规则冲突 → 优先级+精确度
- 残骸 skill → 启动弹窗
- 插件崩溃 → 降级不阻塞
